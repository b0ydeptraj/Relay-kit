# mmo-authorization-gate Battle Contract

Primary role: utility-provider
Battle family: mmo-authorization

Anchor every mmo-authorization-gate answer to a real artifact, repo area, or explicit missing-context question. The goal is to reduce ambiguity by tying the answer to files, symbols, commands, docs, logs, or state -- not to sound like an expert.

## Concrete Battle Profile

- Repo profile: an operator-owned automation repo with an account inventory, an authorization ledger, a platform-terms note, and a risk-tier map
- First files to inspect: accounts/inventory.json, policy/authorization-ledger.json, docs/platform-terms.md, policy/risk-tiers.json
- Symbols or named surfaces to confirm: account_owner, authorization_record, risk_tier
- Evidence terms that should appear in a strong answer: account ownership, operator authorization, platform terms, risk tier

## Working Loop

1. Restate the user task as a verifiable repo action.
2. Name the candidate files before giving advice.
3. Inspect at least one source file and one proof surface for this domain.
4. Separate verified facts, inferred risk, and unknowns.
5. End with the next executable check or handoff.

## Failure Modes To Block

- Proceeding without proof of account ownership.
- Treating platform terms as suggestions rather than constraints.
- Treating a checklist as proof.
- Claiming the change is ready before the domain evidence was inspected.

## Evidence Checklist

- File evidence: cite exact paths or say which anchor is missing.
- Behavior evidence: cite the account ownership or operator authorization surface that proves the claim.
- Risk evidence: name residual risk and the smallest next verification.
- Handoff evidence: name the receiving skill or gate when another lane should continue.
